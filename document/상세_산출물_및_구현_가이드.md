# Azure 기반 물류센터 프로젝트 상세 산출물 및 구현 가이드

## 2. 데이터베이스 상세 ERD 및 테이블/컬럼 정의서

### 2.1 주요 엔터티 및 관계(ERD)
- 센터(Center) —< 존(Zone) —< 라인(Line) —< 구간(Section) —< 센서(Sensor)
- 바스켓(Basket), 컨테이너(Container), 차량(Vehicle) — 센터/라인/구간과 연관
- 병목 이벤트(BottleneckEvent), KPI, 손실 분석(LossAnalysis), 집계(Aggregation) 등 분석/집계 엔터티

### 2.2 테이블/컬럼 예시 정의

#### Center
| 컬럼명         | 타입         | 설명           |
| -------------- | ------------ | -------------- |
| center_id      | INT (PK)     | 센터 고유 ID   |
| name           | VARCHAR(100) | 센터명         |
| location       | VARCHAR(200) | 주소/위치      |
| config_json    | JSON         | 커스텀 설정    |
| created_at     | DATETIME     | 생성일         |

#### Zone
| 컬럼명         | 타입         | 설명           |
| -------------- | ------------ | -------------- |
| zone_id        | INT (PK)     | 존(구역) 고유 ID|
| center_id      | INT (FK)     | 센터 ID        |
| name           | VARCHAR(100) | 존명           |
| description    | VARCHAR(200) | 설명           |
| created_at     | DATETIME     | 생성일         |

#### Line
| 컬럼명         | 타입         | 설명           |
| -------------- | ------------ | -------------- |
| line_id        | INT (PK)     | 라인 고유 ID   |
| center_id      | INT (FK)     | 센터 ID        |
| name           | VARCHAR(100) | 라인명         |
| ...            | ...          | ...            |

#### Section, Sensor, Basket, Container, Vehicle 등도 유사하게 정의

#### BottleneckEvent
| 컬럼명         | 타입         | 설명           |
| -------------- | ------------ | -------------- |
| event_id       | INT (PK)     | 이벤트 ID      |
| center_id      | INT (FK)     | 센터 ID        |
| zone_id        | INT (FK)     | 존(구역) ID    |
| line_id        | INT (FK)     | 라인 ID        |
| section_id     | INT (FK)     | 구간 ID        |
| sensor_id      | INT (FK)     | 센서 ID        |
| occurred_at    | DATETIME     | 발생 시각      |
| duration_sec   | INT          | 지속 시간(초)  |
| cause          | VARCHAR(200) | 원인           |
| affected_basket| INT (FK)     | 영향 바스켓    |

#### KPI, LossAnalysis, Aggregation 등도 유사하게 정의

## 3. API 명세서(입출력, 인증, 오류 처리 등)

### 3.1 예시: 센서 데이터 수집 API
- Endpoint: POST /api/sensor-events
- Request Body: { center_id, line_id, section_id, sensor_id, event_type, value, timestamp }
- Response: { result: "ok", event_id }
- 인증: JWT, Azure AD, API Key 등
- 오류: 400(입력오류), 401(인증실패), 500(서버오류)

### 3.2 예시: KPI 집계 조회 API
- Endpoint: GET /api/kpi?center_id=...&date=...
- Response: { center_id, date, kpi_type, value }

## 5. 센서/장비 연동 및 데이터 제너레이터(시뮬레이터)

실제 물리적 장치 없이 개발·테스트를 진행해야 하므로, 센서 이벤트 데이터를 생성하는 데이터 제너레이터(시뮬레이터)가 필요합니다.

### 5.1 데이터 제너레이터 설계
- 센터/라인/구간/센서별로 임의의 이벤트(바스켓 도착, 병목 발생 등) 생성
- 이벤트 타입, 값, 타임스탬프, 센서 ID 등 랜덤/시나리오 기반 생성
- MQTT, HTTP 등 다양한 방식으로 IoT Hub 또는 API 엔드포인트에 전송
- 장애/이상 상황, 병목 등 특수 이벤트도 시뮬레이션 가능

### 5.2 데이터 제너레이터 샘플 코드 (Python)
```python
import paho.mqtt.client as mqtt
import random, time, json

client = mqtt.Client()
client.connect('iot-hub-endpoint', 1883)

def generate_event():
  event = {
    'event_type': random.choice(['basket_arrival', 'bottleneck', 'container_move']),
    'value': random.randint(0, 10),
    'timestamp': time.strftime('%Y-%m-%dT%H:%M:%SZ'),
    'center_id': random.randint(1, 3),
    'zone_id': random.randint(1, 4),
    'line_id': random.randint(1, 5),
    'section_id': random.randint(1, 10),
    'sensor_id': random.randint(1, 20)
  }
  topic = f"/center/{event['center_id']}/line/{event['line_id']}/section/{event['section_id']}/sensor/{event['sensor_id']}"
  client.publish(topic, json.dumps(event))

while True:
  generate_event()
  time.sleep(random.uniform(0.5, 2.0))
```

이 코드는 센터/라인/구간/센서별로 임의의 이벤트를 생성하여 MQTT로 전송하는 예시입니다. 실제 개발 환경에 맞게 수정하여 활용할 수 있습니다.

## 8. Azure Stream Analytics → Azure PostgreSQL 실시간 ETL 파이프라인 설계 및 구현 가이드

### 8.1 전체 데이터 흐름
- IoT Hub → Stream Analytics(ASA) → Azure PostgreSQL
- 센서 이벤트, 병목, 바스켓 등 실시간 데이터 ASA에서 ETL 처리 후 DB 저장
- ASA Output: env 파일의 AZ_POSTGRE_DATABASE_URL 등 DB 정보 활용

### 8.2 env 파일 DB 정보 예시
```
AZ_POSTGRE_DATABASE_SVR=azpostgredb.postgres.database.azure.com

```

### 8.3 ASA Output 설정 예시
- ASA Job Output: PostgreSQL
- Connection string: env 파일 AZ_POSTGRE_DATABASE_URL 사용
- 테이블: sensor_event, bottleneck_event 등

### 8.4 테이블 생성 예시 (PostgreSQL)
```sql
CREATE TABLE sensor_event (
  event_id SERIAL PRIMARY KEY,
  center_id INT,
  zone_id INT,
  line_id INT,
  section_id INT,
  sensor_id INT,
  event_type VARCHAR(50),
  value INT,
  occurred_at TIMESTAMP
);

CREATE TABLE bottleneck_event (
  event_id SERIAL PRIMARY KEY,
  center_id INT,
  zone_id INT,
  line_id INT,
  section_id INT,
  sensor_id INT,
  occurred_at TIMESTAMP,
  duration_sec INT,
  cause VARCHAR(200),
  affected_basket INT
);
```

### 8.5 ASA 쿼리 예시 (센서 이벤트 → DB)
```sql
SELECT
  center_id,
  zone_id,
  line_id,
  section_id,
  sensor_id,
  event_type,
  value,
  System.Timestamp AS occurred_at
INTO sensor_event
FROM iothub_input
WHERE event_type = 'basket_arrival' OR event_type = 'container_move';
```

### 8.6 실제 진행 단계
1. env 파일 DB 정보 확인 및 PostgreSQL 테이블 생성
2. ASA Job 생성, Input(IoT Hub), Output(PostgreSQL) 설정
3. ASA 쿼리 작성 및 배포
4. 실시간 데이터 흐름 테스트 및 검증
5. DB에 데이터 적재 확인, 쿼리/분석/시각화 연동

## 9. ASA Output 연동 및 실시간 적재 테스트 가이드

### 9.1 ASA Output(PostgreSQL) 연결 방법
1. Azure Portal에서 Stream Analytics Job 생성
2. Input: IoT Hub, Output: PostgreSQL 선택
3. Output 연결 정보에 env의 AZ_POSTGRE_DATABASE_URL 값 입력
4. Output 테이블명: sensor_event, bottleneck_event 등 지정

### 9.2 ASA 쿼리 예시
```sql
-- 센서 이벤트 적재
SELECT
  center_id,
  zone_id,
  line_id,
  section_id,
  sensor_id,
  event_type,
  value,
  System.Timestamp AS occurred_at
INTO sensor_event
FROM iothub_input
WHERE event_type = 'basket_arrival' OR event_type = 'container_move';

-- 병목 이벤트 적재
SELECT
  center_id,
  zone_id,
  line_id,
  section_id,
  sensor_id,
  System.Timestamp AS occurred_at,
  duration_sec,
  cause,
  affected_basket
INTO bottleneck_event
FROM iothub_input
WHERE event_type = 'bottleneck';
```

### 9.3 실시간 적재 테스트 및 검증
1. 데이터 제너레이터 실행 (IoT Hub로 이벤트 전송)
2. ASA Job 실행 및 Output(PostgreSQL)로 데이터 적재
3. DB에서 데이터 적재 확인 (예: SELECT * FROM sensor_event ORDER BY event_id DESC LIMIT 10;)
4. 데이터 누락/지연/오류 발생 시 ASA Job 로그 및 DB 연결 정보 점검

## 10. ASA → DB 데이터 적재 검증 및 쿼리 예시

- 데이터 제너레이터 실행 후 DB에 데이터가 정상적으로 쌓이는지 확인
- 주요 쿼리 예시:
  ```sql
  -- 센터별 이벤트 집계
  SELECT center_id, COUNT(*) AS event_count
  FROM sensor_event
  GROUP BY center_id;

  -- 병목 이벤트 최근 10건
  SELECT * FROM bottleneck_event
  ORDER BY occurred_at DESC
  LIMIT 10;
  ```
- 데이터 검증 방법:
  1. 데이터 제너레이터 실행
  2. ASA Job 실행 및 Output(PostgreSQL)로 데이터 적재
  3. DB에서 쿼리 실행하여 데이터 확인
  4. 누락/지연/오류 발생 시 ASA Job 로그 및 DB 연결 정보 점검

## 11. 집계·분석 작업의 Azure Fabric/Synapse 활용

- 센서 이벤트 등 실시간 데이터는 Azure PostgreSQL에 저장
- 대규모 집계, KPI, 트렌드, 예측 등 분석 작업은 Azure Fabric, Synapse, Data Lake에서 수행
- ETL/ELT 파이프라인(Data Factory, Synapse Pipeline, Fabric Dataflow 등)으로 PostgreSQL 데이터를 Fabric 데이터 레이크/웨어하우스에 적재
- Fabric/Synapse에서 SQL, Spark, Dataflow 등으로 집계/분석 쿼리 작성 및 자동화
- Power BI, 웹 대시보드 등과 연동하여 시각화
- 실시간 저장(PostgreSQL)과 집계/분석(Fabric/Synapse) 역할 분리
