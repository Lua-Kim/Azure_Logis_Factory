    # Azure 기반 물류센터 컨베이어 레일 시스템 아키텍처 및 데이터 모델 설계서
    
    ## 1. 개요
    
    이 문서는 Azure 기반 물류센터 컨베이어 벨트 레일 시스템의 전체 아키텍처와 데이터 모델(테이블 구조, 지표 커버리지)을 정리한 설계 문서이다.  
    IoT 센서/장비에서 발생하는 이벤트를 Azure IoT Hub–Stream Analytics–DB–Data Lake/Synapse/Fabric–Web App으로 처리하고, 운영·분석·예측·시뮬레이션까지 확장하는 것을 목표로 한다.
    
    ---
    
    ## 2. 주요 컴포넌트별 설계
    
    ### 2.1 IoT 센서 및 IoT Hub
    
    - 센터별/라인별/구간별/센서별 Device 등록 및 관리  
    - 바스켓, 병목, 컨테이너, 차량 등 다양한 센서 이벤트 수집  
    - 메시지 라우팅: 센터별/라인별로 구분된 메시지 라우팅 정책 적용 (예: Hub 라우팅, 메시지 속성 기반 라우팅)
    
    ### 2.2 Azure Stream Analytics (ASA)
    
    - 실시간 이벤트 처리: 병목 감지, 대기 시간 계산, KPI 산출  
    - 이벤트 트리거: 임계치 초과 시 알림(Logic App, Functions, Event Grid 등), 자동 조치  
    - Output: Azure PostgreSQL / Azure SQL / Data Lake 등 다중 Output 구성
    
    ### 2.3 데이터 저장 (Azure PostgreSQL, Azure SQL)
    
    - 센터별, 라인별, 구간별, 이벤트별 테이블 설계  
    - Hot/Cold 데이터 분리, 파티셔닝, 인덱싱 전략 수립  
    - KPI, 병목, 손실, 집계 데이터 저장용 스키마 구성

    ### 2.3.1 데이터 원천 구분(제너레이터/ASA 기반 vs 샘플 시드)

    아래는 현재 구현 기준으로 실제 스트림 데이터 기반과 샘플(시드) 기반 데이터를 구분한 목록이다.

    - 제너레이터/ASA 기반(실시간 적재)
      - sensor_event: 제너레이터 이벤트 적재
      - bottleneck_event: ASA 병목 감지 결과
      - kpi_report: ASA 처리량 집계 결과
      - line_status: ASA 라인 상태 집계 결과

    - 샘플(시드) 기반(개발/검증용)
      - equipment, worker, maintenance_event, operation_cost, order_event, quality_event
      - weather, threshold_config, simulation_result
      - bottleneck_event_sensor: 병목-이벤트 매핑 임시 로직
      - aggregation_summary, loss_analysis: kpi_report/bottleneck_event 기반 계산 샘플

    ### 2.3.2 멀티 센터 저장 전략(결정안)

    - 단일 DB + 파티셔닝을 기본 전략으로 사용한다.
    - 보안은 단일 DB 내에서 권한/정책으로 일관되게 적용한다.
    - 센터별 분리 스키마/DB는 운영 복잡도 증가로 인해 채택하지 않는다.
    - 단일 DB 내에서도 센터별 논리 분리를 위해 테이블/파티션을 구분한다.
    
    ### 2.4 데이터 레이크/웨어하우스 (Data Lake, Synapse, Fabric)
    
    - 대용량 원천 데이터 저장, 장기 이력 데이터 관리  
    - ETL/ELT 파이프라인: Raw → Clean → Aggregated  
    - 집계, 트렌드, 예측, AI/ML 분석 및 시뮬레이션 지원
    
    ### 2.5 Web App (대시보드)
    
    - 실시간 현황, KPI, 병목, 손실, 집계 데이터 시각화 (그래프, 히트맵, 표 등)  
    - 센터/라인/구간별 커스텀 설정, 프리셋 관리 UI  
    - 사용자/권한 관리, 알림(메일/SMS/Push), 모바일 대응
    
    ### 2.6 자동화 및 운영
    
    - IaC(Bicep/Terraform)로 인프라 및 플랫폼 리소스 자동 배포  
    - CI/CD: Azure DevOps, GitHub Actions로 애플리케이션/ASA/DB 스키마 배포 자동화  
    - 모니터링: Azure Monitor, Application Insights, Log Analytics  
    - 장애 복구: Azure Site Recovery, Geo-Replication, 백업/복구 정책

    ## 3. 데이터 모델/이벤트 구조 확장 및 고도화 설계
    
    ### 3.1 센서/이벤트 공통 구조
    
    공통 필드 예시:
    
    - 공통: `event_id`, `event_type`, `occurred_at`, `center_id`, `zone_id`, `line_id`, `section_id`, `sensor_id`  
    - 대상 객체 ID: `basket_id`, `container_id`, `vehicle_id` 등 (nullable)  
    - 작업자 정보: `worker_id` (nullable)  
    - 병목 관련: `duration_sec`, `cause`, `affected_basket`, `result`, `detail_reason` 등  
    - 센서/장비 상태: `status`, `error_code`, `error_message` 등  
    - 이벤트 간 연관: `prev_event_id`, `next_event_id`, `route_id` 등  
    - KPI/손실/트렌드 분석용: `target_value`, `sla`, `predicted_value` 등  
    
    이 공통 구조를 기반으로, 아래와 같이 마스터/이벤트/이력 테이블을 설계한다.

    ## 4. 테이블 구조 설계
    
    ### 4.1 센터/존/라인/구간/센서 마스터
    
    #### 4.1.1 개요
    
    | 테이블 | 목적 | 주요 컬럼 | 비고 |
    | --- | --- | --- | --- |
    | center | 물류센터(사이트) 정의 | center_id, name, location, status, opened_at | 상위 엔터티(Site) |
    | zone | 센터 내 존/구역 | zone_id, center_id, name, type, status | 피킹존, 적치존 등 |
    | line | 컨베이어 라인 단위 | line_id, center_id, name, type, status | 메인/서브 라인 구분 |
    | section | 라인 내 구간 | section_id, line_id, name, order_in_line, type | 병목·체류 시간 분석 단위 |
    | sensor | 센서/장비 센싱 포인트 | sensor_id, section_id, equipment_id, sensor_type, name, status | 속도/존재/환경 센서 구분 |
    
    #### 4.1.2 예시 DDL
    
    ```sql
    CREATE TABLE center (
      center_id   BIGSERIAL PRIMARY KEY,
      name        VARCHAR(100) NOT NULL,
      location    VARCHAR(200),
      status      VARCHAR(20),
      opened_at   DATE
    );
    
    CREATE TABLE zone (
      zone_id   BIGSERIAL PRIMARY KEY,
      center_id BIGINT NOT NULL REFERENCES center(center_id),
      name      VARCHAR(100),
      type      VARCHAR(50),
      status    VARCHAR(20)
    );
    
    CREATE TABLE line (
      line_id   BIGSERIAL PRIMARY KEY,
      center_id BIGINT NOT NULL REFERENCES center(center_id),
      name      VARCHAR(100),
      type      VARCHAR(50),
      status    VARCHAR(20)
    );
    
    CREATE TABLE section (
      section_id    BIGSERIAL PRIMARY KEY,
      line_id       BIGINT NOT NULL REFERENCES line(line_id),
      name          VARCHAR(100),
      order_in_line INT,
      type          VARCHAR(50)
    );
    
    CREATE TABLE sensor (
      sensor_id    BIGSERIAL PRIMARY KEY,
      section_id   BIGINT REFERENCES section(section_id),
      equipment_id BIGINT,
      sensor_type  VARCHAR(50),
      name         VARCHAR(100),
      status       VARCHAR(20)
    );

### 4.3 센서 이벤트(sensor_event)

#### 4.3.1 목적 및 특징

* IoT 센서/장비에서 발생하는 모든 이벤트·측정값 로그 저장
* 고빈도 쓰기, 시간 파티셔닝, Hot/Cold 분리, JSON 확장 필드 포함

#### 4.3.2 컬럼 정의

| 컬럼명 | 타입  | 설명  |
| --- | --- | --- |
| event_id | BIGSERIAL (PK) | 이벤트 ID |
| event_type_code | VARCHAR(50) | 이벤트 타입 코드(도착, 출발, 오류 등) |
| occurred_at | TIMESTAMP | 발생 시각 |
| center_id, zone_id, line_id, section_id | BIGINT | 위치 정보 |
| sensor_id | BIGINT | 센서 ID |
| basket_id, container_id, vehicle_id | BIGINT | 대상 객체 ID(바스켓/컨테이너/차량) |
| worker_id | BIGINT | 관련 작업자 |
| numeric_value | DOUBLE PRECISION | 측정값(수치형) |
| string_value | VARCHAR(200) | 측정값/상태(문자형) |
| status | VARCHAR(20) | 센서/장비 상태 |
| error_code, error_message | VARCHAR | 오류 정보 |
| prev_event_id, next_event_id | BIGINT | 이전/다음 이벤트 참조 |
| route_id | BIGINT | 이동 경로 ID |
| target_value, sla, predicted_value | DOUBLE PRECISION | KPI/목표/예측값 |
| attributes_json | JSONB | 확장 속성(유연한 스키마) |

#### 4.3.3 예시 DDL

    CREATE TABLE sensor_event (
      event_id        BIGSERIAL PRIMARY KEY,
      event_type_code VARCHAR(50) NOT NULL,
      occurred_at     TIMESTAMP NOT NULL,
      center_id       BIGINT NOT NULL,
      zone_id         BIGINT,
      line_id         BIGINT,
      section_id      BIGINT,
      sensor_id       BIGINT,
      basket_id       BIGINT,
      container_id    BIGINT,
      vehicle_id      BIGINT,
      worker_id       BIGINT,
      numeric_value   DOUBLE PRECISION,
      string_value    VARCHAR(200),
      status          VARCHAR(20),
      error_code      VARCHAR(50),
      error_message   VARCHAR(500),
      prev_event_id   BIGINT,
      next_event_id   BIGINT,
      route_id        BIGINT,
      target_value    DOUBLE PRECISION,
      sla             DOUBLE PRECISION,
      predicted_value DOUBLE PRECISION,
      attributes_json JSONB
    );

### 4.4 병목 이벤트(bottleneck_event)

#### 4.4.1 목적 및 특징

* 병목 구간·지연 이벤트를 요약해 관리하고, 원인/영향 분석에 활용
* 요약 이벤트 + 관련 sensor_event 맵핑 구조

#### 4.4.2 컬럼 정의

| 컬럼명 | 타입  | 설명  |
| --- | --- | --- |
| bottleneck_id | BIGSERIAL (PK) | 병목 이벤트 ID |
| root_event_id | BIGINT | 대표/트리거 이벤트 ID |
| occurred_at | TIMESTAMP | 병목 발생 시각(시작) |
| center_id, zone_id, line_id, section_id | BIGINT | 위치 정보 |
| sensor_id | BIGINT | 대표 센서 |
| duration_sec | BIGINT | 지속 시간(초) |
| cause_code | VARCHAR(50) | 병목 원인 코드(장비, 작업자, 설계 등) |
| affected_basket | BIGINT | 영향 받은 바스켓 |
| result_code | VARCHAR(50) | 처리 결과 코드 |
| detail_reason | VARCHAR(500) | 상세 사유 |
| worker_id | BIGINT | 담당 작업자 |
| status | VARCHAR(20) | 처리 상태 |
| error_code, error_message | VARCHAR | 관련 오류 |

#### 4.4.3 예시 DDL

    CREATE TABLE bottleneck_event (
      bottleneck_id   BIGSERIAL PRIMARY KEY,
      root_event_id   BIGINT,
      occurred_at     TIMESTAMP NOT NULL,
      center_id       BIGINT NOT NULL,
      zone_id         BIGINT,
      line_id         BIGINT,
      section_id      BIGINT,
      sensor_id       BIGINT,
      duration_sec    BIGINT,
      cause_code      VARCHAR(50),
      affected_basket BIGINT,
      result_code     VARCHAR(50),
      detail_reason   VARCHAR(500),
      worker_id       BIGINT,
      status          VARCHAR(20),
      error_code      VARCHAR(50),
      error_message   VARCHAR(500)
    );
    
    CREATE TABLE bottleneck_event_sensor (
      bottleneck_id BIGINT NOT NULL REFERENCES bottleneck_event(bottleneck_id),
      event_id      BIGINT NOT NULL,
      PRIMARY KEY (bottleneck_id, event_id)
    );

## 5. 도출 가능한 주요 지표 및 분석 항목

### 5.1 처리량/흐름 관련

* 센터/존/라인/구간/센서별 단위 시간(분/시간/일)별 처리량
* 시간대별, 요일별, 월별 처리량 트렌드
* 센터/라인/구간별 TOP N 처리량 구간
* 실시간/집계 처리량 변화 추이

### 5.2 병목/지연/이상 관련

* 병목 이벤트 발생 빈도, 지속 시간, 주요 발생 구간/라인/시간대
* 병목 원인별(센서, 장비, 작업자 등) 통계
* 병목/지연으로 인한 생산성 손실 추정
* 비정상 이벤트(센서 오류, 장비 고장 등) 발생률
* 실시간 이상 감지/알림 이벤트

### 5.3 KPI/성과/효율 관련

* 평균 처리 시간, 평균 대기 시간, 평균 이동 거리
* SLA(서비스 수준) 준수율, 목표 대비 실적
* 작업자별/장비별 성과 및 효율성
* 센터/라인/구간별 KPI 달성률

### 5.4 객체/경로/이력 분석

* 바스켓/컨테이너/차량별 이동 경로 및 처리 이력
* 객체별 체류 시간, 이동 거리, 처리 단계별 소요 시간
* 작업자별 작업 이력, 장비별 가동/비가동 이력

### 5.5 트렌드/예측/AI 분석

* 시간대/요일/월별 트렌드 분석
* AI/ML 기반 병목/이상 예측, 수요 예측
* KPI/이상/병목 등 미래 예측 및 시뮬레이션

### 5.6 운영/설비/유지보수·ESG·비용

* 장비별 가동률, 고장률, 평균 무고장 시간(MTBF), 평균 수리 시간(MTTR)
* 센서/장비별 점검 이력, 예방 정비 필요 예측
* 센터/라인/구간별 운영비용, 인건비, 에너지비, 유지보수비
* 에너지 사용량, 탄소 배출량 추정, 환경 센서 기반 ESG 지표

### 5.7 고객/서비스/품질 및 외부 연계

* 주문별 처리 리드타임, 배송 지연률, SLA 위반 건수
* 고객별/상품별 처리 현황, 클레임/반품률 (추가 테이블 연계)
* 날씨/교통/공휴일 등 외부 요인과의 상관 분석

| IoT 메시지 성공률, 장애/복구, 데이터 품질 | 부분 가능 | 이벤트 수집/오류 이벤트로 일부 가능, 시스템 장애/복구/품질 모니터링은 별도 테이블 필요 |
| 시뮬레이션/디지털 트윈 | 부분 가능 | event 데이터 활용 가능, 시뮬레이션/트윈 결과는 별도 테이블 필요 |

#### 7.3.1 데이터 제너레이터 보안 운영 플랜(Key Vault 연동)

* 운영 환경에서는 로컬 .env를 사용하지 않고 Key Vault에서 연결 문자열을 조회한다.
* 데이터 제너레이터는 VM/컨테이너에서 실행하며 Managed Identity를 활성화한다.
* Key Vault에 IoT Hub 연결 문자열을 Secret으로 등록한다.
* Managed Identity에 Secret 조회 권한(Get, List)을 부여한다.
* 제너레이터는 실행 시 Key Vault에서 Secret을 읽어 IoT Hub에 연결한다.
* 센터별 실행은 --center-id 인자로 구분하며, 센터별 인스턴스를 별도로 실행한다.

### 7.4 4단계: 데이터 분석 및 집계

## 10. 웹 대시보드 상세 화면 설계

### 10.1 페이지 구성(IA)

* 본사 통합 대시보드(멀티 센터 집계)
* 센터 상세 대시보드(라인/구간 중심)
* 라인 분석(수치/용량/병목 요약)
* 병목/이상 분석(원인/분포/추이)
* KPI/리포트(기간별 성과)
* 설정(센터/존/레일/센서/임계치)

### 10.2 본사 통합 대시보드(멀티 센터)

* 상단 KPI 카드: 총 처리량, 평균 SLA, 활성 병목, 이상 이벤트 수
* 집계 그래프
  - 센터별 처리량 비교(막대)
  - 센터별 SLA 준수율(스택 막대)
  - 시간대별 전체 처리량 추이(라인)
  - 병목 발생 Top N 센터(가로 막대)
* 표
  - 센터 요약 표: 센터 ID, 라인 수, 활성 병목 수, 최근 업데이트, 상태
  - 최근 병목 이벤트 표: 센터/라인/구간/지속시간/원인
* 필터
  - 기간(5m/1h/24h/7d), 센터 그룹, 상태(정상/주의/경고)

### 10.3 센터 상세 대시보드

* 상단 KPI 카드: 라인 수, 활성 병목, 평균 처리량, 평균 지연
* 그래프
  - 라인별 처리량(막대)
  - 라인별 평균 지연(막대)
  - 구간별 병목 빈도 히트맵(행: 라인, 열: 구간)
  - 시간대별 처리량/지연 추이(이중 라인)
* 표
  - 라인 상태 표: line_id, 상태, 활성 병목, 최근 바스켓, 갱신 시각
  - 최근 이벤트 표: event_type, line_id, section_id, occurred_at
* 필터
  - 존/라인/기간/상태 필터

### 10.4 라인 분석(수치 중심)

* 라인 기본 수치
  - 레일 길이, 구간 수, 센서 수, 최대 센서 허용치
* 계산 규칙(설정 기반)
  - 센서 최대치: $sensor_{max} = 2 \times rail\_length\_m$
  - 바스켓 길이: $basket\_length\_m = 0.5$
  - 라인 최대 적재 바스켓 수: $capacity = \lfloor rail\_length\_m / 0.5 \rfloor$
* 그래프
  - 시간대별 라인 처리량(라인)
  - 병목 지속시간 분포(히스토그램)
  - 센서/구간별 이벤트 밀도(히트맵)
* 표
  - 구간별 평균 체류 시간, 병목 빈도, SLA 이탈률

### 10.5 병목/이상 분석

* 그래프
  - 원인별 병목 비중(도넛)
  - 구간별 병목 누적 시간(막대)
  - 시간대별 병목 발생 추이(라인)
* 표
  - 병목 상세: 발생 시각, 라인/구간, 지속 시간, 원인, 상태
  - 이상 이벤트: error_code, 빈도, 최근 발생 시각

### 10.6 KPI/리포트

* 그래프
  - SLA 준수율 추이(라인)
  - 처리량/지연 상관 그래프(산점)
  - 센터/라인 KPI 달성률(히트맵)
* 표
  - KPI 요약: center_id, line_id, throughput_count, 평균 지연, SLA

### 10.7 설정 페이지(범용 센터 시스템)

* 센터 설정
  - 센터명, 위치, 상태, 운영 시작일
* 존 설정
  - 존명, 타입, 상태
* 레일(라인) 설정
  - 레일 수, 레일 길이(m), 구간 수, 상태
* 센서 설정
  - 센서 수, 타입, 상태
  - 센서 수는 레일 길이의 2배 이하로 제한
* 임계치 설정
  - 병목 감지 임계치, SLA 기준, 알림 조건

### 10.8 설정 데이터 구조(예시)

* center_config(center_id, name, location, status, opened_at)
* zone_config(zone_id, center_id, name, type, status)
* rail_config(line_id, center_id, name, status, rail_length_m, section_count)
* sensor_config(sensor_id, line_id, section_id, sensor_type, status)
* threshold_config(config_key, config_value, description)

### 10.9 화면 공통 규칙

* 애니메이션/실시간 움직임 시각화는 제외(수치 기반)
* 모든 그래프는 기간 필터 공통 적용
* 실시간 데이터는 고정 주기(예: 5s) 갱신 또는 WS 기반 업데이트

## 11. 설정 페이지용 API/DB 구조 정의

### 11.1 설정 입력 원칙

* 설정은 반드시 UI에서 입력한다.
* 데이터 제너레이터는 설정 데이터 범위를 벗어나지 않도록 동기화한다.
* 센터 수는 약 50개 기준으로 설계하고, 목록은 페이징/검색을 지원한다.

### 11.2 설정 관련 DB 테이블(운영 반영)

* center (기존)
  - center_id, name, location, status, opened_at
* zone (기존)
  - zone_id, center_id, name, type, status
* line (기존)
  - line_id, center_id, name, type, status
* section (기존)
  - section_id, line_id, name, order_in_line, type
* sensor (기존)
  - sensor_id, section_id, equipment_id, sensor_type, name, status
* threshold_config (기존)
  - config_id, config_key, config_value, description

### 11.3 설정 API(초기 정의)

* GET /api/settings/centers?page=&size=&q=
* POST /api/settings/centers
* PUT /api/settings/centers/{center_id}
* GET /api/settings/centers/{center_id}/zones
* POST /api/settings/zones
* GET /api/settings/centers/{center_id}/lines
* POST /api/settings/lines
* GET /api/settings/lines/{line_id}/sections
* POST /api/settings/sections
* GET /api/settings/lines/{line_id}/sensors
* POST /api/settings/sensors
* GET /api/settings/thresholds
* PUT /api/settings/thresholds/{config_key}

### 11.4 설정 검증 규칙(필수)

* 센서 수 제한: line별 센서 수 <= 2 * rail_length_m
* 바스켓 길이 고정: 0.5m
* 라인 적재량 계산: floor(rail_length_m / 0.5)
* zone/line/section/sensor는 반드시 center_id 기준으로 연결 일관성 유지

### 11.5 데이터 제너레이터 연동 체크

* generator가 참조하는 center_id/zone_id/line_id/section_id/sensor_id 범위가 설정 데이터에 포함되어야 함
* 설정 페이지 저장 시, generator 기준 범위와 불일치 발생 시 경고 표시
* 최소 기본 데이터: center_id=1, zone_id 1..3, line_id 1..5, section_id 1..10, sensor_id 1..5

### 11.6 DB 스키마 변경 실행(별도 스크립트)

* 기존 DB에 컬럼 추가가 필요한 경우, 아래 스크립트를 실행한다.
  - backend/alter_tables.py
* 변경 대상
  - line.rail_length_m
  - line.section_count

### 11.7 라인 분석 조회 API(시간/일/월/연도)

* GET /api/line/analytics?line_id=&granularity=&start_ts=&end_ts=
* granularity: hour | day | month | year
* 기본 기간: 최근 24시간
* 반환: bucket별 event_count, arrival_count, departure_count

## 12. 화면 와이어프레임(텍스트 설계)

### 12.1 본사 통합 대시보드

* 상단 KPI: 총 처리량 | 평균 SLA | 활성 병목 | 이상 이벤트
* 차트 영역: 센터별 처리량(막대), SLA 준수율(스택), 전체 처리량 추이(라인)
* 표 영역: 센터 요약 테이블, 최근 병목 이벤트 테이블
* 우측 필터: 기간, 센터 그룹, 상태

### 12.2 센터 상세 대시보드

* 상단 KPI: 라인 수 | 활성 병목 | 평균 처리량 | 평균 지연
* 차트: 라인별 처리량(막대), 라인별 평균 지연(막대), 구간 히트맵
* 표: 라인 상태, 최근 이벤트
* 필터: 존/라인/기간/상태

### 12.3 라인 분석 페이지

* 요약 카드: 레일 길이, 센서 수, 구간 수, 최대 적재 바스켓
* 기간 탭: 시간대 | 일별 | 월별 | 연도별
* 차트: 처리량 추이(라인), 병목 지속시간 분포(히스토그램), 이벤트 밀도(히트맵)
* 표: 구간별 평균 체류 시간, 병목 빈도, SLA 이탈률

### 12.4 병목/이상 분석

* 차트: 원인별 병목(도넛), 구간별 누적 시간(막대), 시간대 추이(라인)
* 표: 병목 상세, 이상 이벤트 요약

### 12.5 KPI/리포트

* 차트: SLA 준수율 추이(라인), 처리량/지연 산점, KPI 달성률 히트맵
* 표: KPI 요약 테이블

### 12.6 설정 페이지

* 센터 목록(페이징/검색) + 센터 상세 편집 폼
* 존/라인/구간/센서 탭 구조
* 검증 메시지: 센서 수 제한, 연관 데이터 일관성
